## 实际修改

`client/scripts/world_visuals.gd` 将维修场入口连续等宽深车辙改成沿曲线变化、断续压实的浅凹槽，去除两侧连续正高度凸唇。宽景前后对比中，原先像挤出土绳的两条长凸脊消失，入口场地更平顺；这属于几何修改，并非整体调色。

道路两侧草坡原先以平地为高度基准，路槽却向下挖掘，导致坡边形成碰撞墙。将坡体基础统一到 `road_cut_height`，保留场地已有基准的特殊区域；顶点法线按最终高度计算。Stage516 失败样本的接触点为 `(-10.5,-0.018,26.00183)`，法线 `(1,0,0)`，对应西侧坡块边界。`tests/graded_road_traversal_review.gd` 增加碰撞位置、法线和网格包围盒诊断，未放宽通行断言。

完整四姿势由 `tools/run_sleeve_pose_review.py` 默认全集运行，没有用单个 `--pose` 替代。其他武器及第三人称由 `run_weapon_contact_review.py --scope other-weapons-and-third` 运行；最终状态及逐帧审阅见下方收尾记录。

当前已审阅默认、ADS、换弹中段及 SG8 换弹中段：支撑前臂呈长锥形，袖口接腕过于收窄，枪托在换弹中占据过大屏幕面积。肩肘多数在第一人称视野外，不能从枪边局部手指接触推断整条手臂自然。握持与弹匣的静态邻近不能证明抽取、插入、回握全过程接触。

`motion/` 为当前 PCK 的三武器 × 第一人称/第三人称站姿/蹲姿九段诊断序列，共261帧，60Hz模拟、每6帧采样。已审阅第一及第三人称序列拼图。该运行使用640×400、简化环境材质、裁除远处细节、关闭阴影等诊断设置，不作为正式环境画质证据。九段时间线完整，但引擎日志出现 material null 错误，因此 `process-result.json` 和 `recovery-audit.json` **均不能记为通过**。`motion/viewer.html` 可本地播放；本轮尚未完成正常画质实时连续动作验收。

第三人称诊断中颈部拉长、肩带及上臂运动僵硬；蹲姿手臂靠近膝盖，需要正常画质近景核对。源码采用通用左手换弹路径和刚性上身倾斜，不能充分表达不同武器的弹匣位置、肩肘补偿。下一阶段优先调整前臂截面和腕袖衔接，以及武器分别定义的支撑/取弹匣/插入/回握目标，配合肩肘运动；不继续以机匣、手指微调代替结构修复。

## 最终包复核

最终 PCK 的七项测试全部通过：车辙、场地坡岸、维修棚入口、场地通行、道路横穿、瞄准伤害和单机 smoke。每项均检查退出码、对应 PASS 标记及引擎错误；原先失败的道路横穿没有放宽断言。正常画质环境三机位与完整四姿势采集进程均通过，PCK 哈希一致。

四姿势全部逐张审阅，补看换弹完成时弹量恢复与回握位置。SR5 换弹中段也已审阅：枪托和瞄具占屏过大，前臂仍细长锥形，腕袖衔接生硬，不能据此确认弹匣插入接触。正常画质第三人称站姿确认颈部偏长、肩部僵硬，手臂与胸前装备拥挤。上述均为待修缺陷，没有把采集成功等同于人物画质通过。

`after/` 是碰撞修复前启动的中间采集，不用于最终验收；正式环境证据只取 `final-environment/` 和对应 `comparison/`。九段诊断虽包含261帧完整时间线，但日志有188条材质空引用错误，整体失败；尚未覆盖正常画质实时连续动作、各武器全程取放弹匣接触及肩肘补偿验收。

其他武器与第三人称四张正常画质截图最终采集成功（退出0，931.91秒），已全部逐张审阅。蹲姿中手臂、弹匣与膝部空间拥挤，颈肩仍有假人感；背景出现悬空角色，需追查角色落地/诊断场景摆放，不能只修近景衣袖。护木握持在默认及回握截图可见，但抽取、插入与回握的连续接触仍未验收。

下一阶段以当前包为基线，先处理人物颈肩比例、前臂截面/袖口和分武器换弹目标，复核肩肘、护木、弹匣及膝部避让；同时定位动作诊断材质空引用。随后继续山体结构、植被差异、建筑内部和光照层次，并补齐联网主要功能。所有目标仍未整体完成。
