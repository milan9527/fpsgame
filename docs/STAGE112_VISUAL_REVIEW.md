# Stage112：仓库内墙与装卸区地坪

本轮是局部环境改进，整体目标继续。未修改武器和人物模型，也未改变光源参数。既有未提交修改全部保留，未推送或发布。

## 改动与实际画面判断

- 仓库侧墙、端墙增加浅色墙裙、深色护条和高位线槽/支架，正常室内机位能辨识墙体分层。附加薄构件不参与碰撞，不缩小入口。
- 装卸棚地坪用混凝土替换夸大的石块纹理；仓内混凝土降低底色亮度，加入不规则色差、边缘积尘和通行带。第一版仍过白，已再降低底色。最终地坪仍显平滑，分缝偏整齐，不能称为真实混凝土成品。
- 碎石、泥土采样尺度缩小，泥土去饱和。宽幅图中植被稀薄、低矮仓库重复、空旷道路与远山棱面仍很明显；本轮没有解决树冠体积或植被接地，也没有完成整体光照改善。
- 木箱纹理仍有模糊拉伸感，入口门框颗粒过粗；室内暗部与户外明部的过渡需要继续审阅。

`environment-before-after.jpg`、`entrance-before-after.jpg` 左为111，右为112；`original-spawn-before-after.jpg` 包含原出生点腰射与瞄准。`source-forward/` 和 `packaged-forward/` 保存最终完整分辨率实机截图，`initial-forward/` 仅保留第一次调色结果，不是最终图。

环境及入口的精确位置、朝向/目标见各目录 `environment-camera-poses.json`、`entrance-camera-poses.json`；最终汇总检查三个版本的记录完全一致。原出生点武器图使用位置 (17,0.05,50)、yaw=atan2(-18,16)、pitch=-0.03，分辨率1280×800。静态审阅冻结游戏；通行由另外的物理移动测试验证。

## 验证边界与后续

功能结果以 `functional-results.json` 为准，截图进程以 `capture-results.json` 和 `operator-result.json` 为准，最终汇总、文件哈希与警告保存在 `verification.json`。最初误用了不存在的 offline_smoke.gd，失败日志单独保留；正确调用是游戏的 `-- --smoke`，不将错误调用计为通过。

人物截图首轮与其他截图争用软件渲染资源，在240秒超时，只产生部分图片，不能计为通过。其他截图结束后独立重试成功，完成站立、蹲姿、换弹、倒地四种姿态各三个角度共12张；首轮日志和返回码保留为 `initial-packaged-operator.log`、`initial-operator-result.json`。完整姿态拼图已实际审阅：手指块状、护具与背包生硬，蹲姿腿部压缩，倒地姿态膝腿关节不自然，站立与换弹也偏僵硬。这些均未达标，证据见 `operator-contact-sheet.jpg`。

独立预览：`artifacts/realism112-preview/Linux/IronMeridian`，同目录 pck；运行方法见预览 README。使用软件 Vulkan llvmpipe，不能代表用户硬件性能。网络状态规则测试不是实际联网；多人联机主要流程仍需补验。

下一阶段优先改善宽幅正常机位的树冠体积、植被接地和院落布局变化，并以同机位检查光照层次；不能再把整轮局限于混凝土地坪或武器细节。继续保留第三人称、第一人称手部、瞄准碰撞及真实多人验证目标。

源码与独立包三枪的腰射、瞄准及三个换弹阶段已实际审阅：枪体可见，第一人称手臂依然细长棱角明显，换弹中段的支撑手接触关系需要动态复查。静态姿态截图成功不代表握持质量达标。独立包入口近景、室内地坪和宽幅地形已逐图核对，画面与源码改动一致。

最终27项检查通过：源码及独立包各10项功能检查、各3项截图采集，以及独立包人物采集。功能覆盖单机烟测、瞄准对齐、武器遮挡、入口/屋顶/掩体碰撞、仓库和棚下双向真实角色物理通行；网络仅状态规则。相机记录一致性、截图尺寸和构建哈希已汇总到 `verification.json`。检查数量不代表画质验收通过。
