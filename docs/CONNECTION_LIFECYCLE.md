# 连接取消与预留释放

部署菜单在登录、匹配或连接过程中启用 CANCEL。取消会返回菜单；也可直接开始单机。每次连接使用本地尝试编号，旧请求的返回值和旧握手定时器不能覆盖新操作。若取消后旧匹配请求才返回票据，客户端使用该请求原来的 API 地址与令牌撤销预留，不把旧令牌发到新地址。

`POST /matchmaking/rooms/cancel` 使用账户 JWT，接收票据字符串。Redis 原子检查票据所属账户，仅移除仍未消费的票据及其对应预留。重复取消返回 inactive。取消与专服消费竞争时只有一方获胜；已消费票据的取消不释放座位，也不会踢掉已入场玩家。旧回合票据不能取消同一用户的新回合预留。

建立连接失败、网络初始化失败、返回菜单、切换单机和退出时，客户端尝试撤销尚未完成入场的票据。请求超时为 2 秒；API 不可达、进程被强制结束或消费已完成但入场未确认时，仍可能需要等待原有租约到期。此机制不是断线重连，也不取消已完成的账户注册。

已入场的退出由专服连接生命周期处理，不能通过账户取消接口任意删除活跃名额。退出程序的可靠离开请求也允许终止尚在鉴权的连接，避免已取消客户端在服务器 HTTP 回应后被接纳。

验证包括：

- 真实 Redis 的账户归属、重复取消、立即重新分配、旧回合保护，以及 12 轮取消/消费并发竞争。
- 图形窗口客户端通过真实 API 获得预留，再连接一个测试 UDP 接收端；点击 CANCEL 后在 6 秒以内重新分配，验证不必等待 45 秒。
- 延迟返回匹配结果的受控测试，验证取消后开始的单机不会被旧请求替换，并核对取消使用原请求的凭据来源。
