# 单机保存与继续

存活且单机回合进行中，在暂停菜单选择 SAVE OPERATION & RETURN。写入成功后返回主菜单，不记作放弃；失败时保持当前对局暂停并显示原因。主菜单 CONTINUE SAVED OPERATION 加载后先暂停，玩家点击 RESUME 才继续模拟。在线对局没有此功能。

当前为一个手动保存槽，已有文件时按钮明确显示 REPLACE SAVED OPERATION & RETURN。开始另一场新单机不会自动删除旧存档，但再次保存会替换它。没有自动保存。直接关闭进行中的游戏或选择 ABANDON 会按既有流程记为放弃，角色被淘汰或回合结束则结算完成。已结算或待写入结算的回合不能再从旧检查点重开；此功能用于挂起继续，不用于死亡后的读档重试。

保存内容包括相同回合 UUID、16 个角色的生命/护甲/三枪弹匣/储备/医疗/投掷物、位置速度和姿态、换弹治疗及射击冷却、机器人目标与最后目击记忆、地图物资、当前及未来缩圈中心、回合时钟与随机状态、在途手雷的位置/速度/角速度/引信、烟雾位置/年龄和个人路标。恢复后重新生成固定地图并重建导航。临时输入、网络历史、音频播放进度、骨骼动画相位和缓存路径不保存，机器人会重新寻路；不是逐帧确定性重放。

文件为 `user://solo_checkpoint.dat`，带格式版本、内容版本和 SHA-256 校验，最多 2 MiB。读取在修改现有场景前检查结构、库存、数值范围和资源数量；不解码可执行对象。内容版本不兼容或损坏时不加载。写入采用同目录临时文件加重命名替换；再次保存前保留上一次有效主文件为 `.bak`。主文件不可读时尝试备份并提示恢复了较早检查点。备份可能属于先前保存的另一场操作，且仍受回合已结算检查约束。首次保存没有旧备份，同盘备份不防磁盘损坏，也不承诺断电耐久性。

本地结果仍使用独立的不可变记录目录。检查点不会上传到在线排行榜，也不更改在线专服状态。恢复前检查已发布结果目录和待存结果，避免同一 UUID 再次结算。校验值用于发现损坏，不是防止用户修改离线存档的安全机制。

`checkpoint_rules.gd` 覆盖状态往返、尸体/库存/计时、手雷/烟雾、缩圈/随机数、保存失败、备份、无放弃记录和已结算隔离。`test_checkpoint_process.py` 使用三个独立 Godot 进程验证关闭进程后继续同一回合，并对发行 PCK 运行同样检查。
