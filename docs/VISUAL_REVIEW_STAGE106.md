# Stage106 环境审阅

本轮继续环境优先：装卸棚钢架表面和底座、地坪外缘泥土碎石、背景林带疏密与尺寸变化、天空环境补光。没有重建武器或人物资产。整体目标仍未完成。

- 棚区：钢架摆脱原来的整片纯黑，立柱、斜撑和底座更易辨认。现用细碎纹理在近景中偏石质，仍不算可信的涂层钢材；后续应采用定向划痕、边缘磨损和更克制的色差。
- 地表：棚边出现泥土碎石过渡带，远于原先硬矩形地坪。但棚下近景仍能找到直线截断，暖色泥土带偏宽，其他道路和车位硬边未处理。不能把这次局部覆盖层当成地形材质问题已解决。
- 植被：远山树木尺寸和空隙发生变化；山脊仍有细长重复树形，平滑山体依然像人工堆出的土丘。近处草团没有在本轮重建，重复、同色和大块空地仍明显。
- 入口：正面近景可见通向后门的通道及两侧货箱。门前坡板过于光滑并有明显高光，墙面和室内仍缺少结构细节。
- 光照：仅提高 Forward+ 天空环境光能量 .60→.72，保留太阳、天空和曝光。阴影中钢架可读性改善，但画面仍偏平，未完成区域灯光和材质响应协调。
- 人物与手部：第一人称前臂依旧偏长直、腕部折角明显。需继续结合换弹接触和第三人称人物实机审阅；本轮不能替代人物审阅。

## 验证范围及复核方式

`test-results.json` 保存每项命令的退出码、PASS 标记和日志路径；`verification.json` 由验证完成后的汇总脚本生成，核对相机一致性并记录源码、资产与预览哈希。`environment-before-after.jpg` 左为105、右为106，仍需结合原分辨率 PNG 判断质量。

截图脚本冻结玩法以稳定机位；独立物理测试驱动真实角色双向通过仓库（x=35，z=44/24）和装卸棚（x=23.5，z=44/24），不能用静态画面替代通行验证。另检查棚柱/顶棚、六根旋转斜撑、两只货箱侧面、入口及屋顶碰撞、单机主要流程、三枪108样本瞄准和武器遮挡。网络检查仅覆盖状态规则，不等于实际多人联机验证。

验证器最初误用了 `DEPOT_COVER_REVIEW_PASS` 标记，而测试实际输出 `DEPOT_COVER_PASS`；已修正标记并重跑该项。原记录保留在 `runner-marker-mismatch.json`，这是验证器判断错误，不是碰撞测试失败。

最后一项导出包武器截图运行曾以 143 中断，原因未确定；当时已保存 27 项通过结果，但武器截图没有完成标记。中断日志保留为 `packaged-capture-interrupted.log`，补跑结果以 `test-results.json` 为准。

最终补跑通过：共 28 条成功记录，最终日志未检出 ERROR/WARNING；前后四个环境机位的位置与朝向完全一致。48 张原始截图包括旧包环境 4 张、本轮源码及包内各 22 张。已审阅环境前后对照、包内三枪五姿态总览及入口、地形、棚下和换弹原图；截图数量仅用于核对采集完整性。最终预览哈希保存在 `build.json` 与 `verification.json`。

使用 llvmpipe 软件 Vulkan；不宣称硬件 GPU 帧率合格。预览为 Godot 4.4.1 可执行文件和相邻导出 PCK，运行说明见 `artifacts/realism106-preview/README.md`。未发布。
