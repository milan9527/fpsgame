# Stage511：三武器九组换弹诊断采集

本轮解决连续动作证据长期采不齐的问题，没有修改游戏模型、场景或预览包，不算画质改善阶段，也不判定整体目标完成。当前预览仍为 `artifacts/realism510-preview/Linux/launch.sh`。

## 方法与边界

采集器增加逐帧等待、绘制、回读、PNG保存耗时记录；新增显式 `--simplify-world-materials` 诊断开关，仅覆盖 world 子树的背景材质，关闭 SSAO/SSIL/MSAA。人物和武器保留原材质。使用 compact 640×400、关闭光源阴影、裁减远处细节，所有这些差异写入清单和本地播放器。没有更改正常预览的渲染配置。

每组先射击，再从换弹开始到完成以固定60Hz推进、每6帧保存一次实机图像。三种武器分别采第一人称、第三人称站立、第三人称蹲姿，共九组261帧。10Hz采样可检查过程中的大幅跳动与轮廓变化，不能证明帧间接触、实时输入、移动换弹、蹲起、射击后坐力或联网同步自然。此轮没有重跑正常画质完整四姿势；Stage510四姿势是同一未改动PCK的上轮证据，不能冒充本轮采集。

## 实际审阅

已逐组查看 `artifacts/realism511-validation/motion-sheets/` 九张全过程接触表，并查看原始第一人称武器0第96帧、武器1第90帧、第三人称蹲姿武器0第66帧、站姿武器2第144帧。接触表来自保留了退出错误的 `motion-simplified/` 试跑，只用于视觉诊断，其测试状态仍为失败。

- 第一人称三武器都有放低左手、持匣、回到枪身的过程，未在这些离散采样中发现整条手臂瞬移。枪托的大块平面与扩张轮廓占据右侧大量画面，前臂仍呈锥管形，袖口连接有明显断层；相比继续微调手指，更值得整体修正枪托体积、袖管截面和握持构图。
- 第三人称站立三武器可见头部俯仰、左手下移和回位。下身基本固定，上半身动作较机械。低分辨率远景不足以判断肩肘细小穿插和护木接触，需要近距离正常画质过程证据。
- 第三人称蹲姿三武器的高膝盖遮住了部分手和弹匣路径。第66帧原图可见手/膝/弹匣区域叠在一起，无法据此判定接触正确。应新增侧面近景并核对蹲姿骨盆、膝盖、肘部与弹匣的空间关系。
- 阴影被关闭，且测试冻结了游戏物理流程；图中离地观感不能证明正常游戏人物悬空。仍需正常物理推进下的落地检查。

## 本轮执行结果

两次简化背景运行都采齐九组261帧，进程退出0，耗时分别237.455秒和214.236秒，但均出现188条材质空引用 ERROR，严格审计 `full_suite_passed=false`。增加延迟释放场景及绘制清理未解决问题，未屏蔽错误。最后一次 `motion-cleanup/` 的261张PNG与已审阅的 `motion-simplified/` 逐一SHA256相同。本地 `motion-cleanup/viewer.html` 提供逐帧播放和失败状态，`recovery-audit.json`、`capture.log`、`process-result.json` 保留可复核结果。

耗时记录见 `artifacts/realism511-validation/runtime-comparison.json`，只衡量诊断采集；不同视角绘制开销差异大，不用整组中位数宣称正常游戏帧率提升。原背景试跑中断记录保留于 `motion-profile/`。本轮没有新增游戏视觉修改或重新导出预览。

## 下一阶段
