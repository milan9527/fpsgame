默认包内容与已验证候选一致，源提交 `9e73c12a`，SHA-256 为 `2b4bc239ed615949237f8a4cba572315bc0cfde157d22a28993b4b71f95b0a27`。解压桌面运行 `./play.sh`，离线 SOLO / DUO 无需账号，在线填写上述 API。旧协议 15 客户端不能连接新服务。

## 切换与数据验证

升级前确认两个房间没有在线玩家、两个结果重试队列为空；保存 PostgreSQL 备份、队列、旧 compose 配置及三个旧服务镜像的回退标签。记录目录为 `artifacts/release-rollout/`。

`tools/restore_drill.py --upgrade-image <后端镜像>` 将 0003 备份恢复到无外部网络、无宿主端口的临时 PostgreSQL，使用指定后端镜像在同一隔离网络命名空间执行实际迁移。升级前后比较用户全部字段及历史对局/战绩的原有字段指纹，并核对行数、历史模式默认值、外键、队伍约束和账户统计关系。镜像解析为具体 image ID，避免演练过程中标签变化。

本次隔离演练与运行库切换均保留原有 **51 个账号、103 场对局、151 条战绩** 的旧字段。新列将历史数据归类为 `solo / team_id=0`。升级后的备份再次恢复成功，其中包含后续测试产生的两场双人对局、四条双人结果及新增单人记录。

恢复工具同时修复了 PostgreSQL 容器初始化的就绪检查：等待 `127.0.0.1` 上的 TCP 服务，避免误将初始化阶段的临时 Unix socket 服务当作最终数据库。
