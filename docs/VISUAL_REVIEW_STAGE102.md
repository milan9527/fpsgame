# Stage102：握把比例与右手包握联动

按 stage31 第一人称优先反馈，本轮联合修改卡宾枪握把和右手形体。`tools/build_assets.py` 将握把纵向尺寸从约 152 mm 缩到 115 mm，并收窄截面、同步调整防滑区域；`tools/build_viewmodel.py` 将原先横向排列的右手手指转为竖向包握，向固定袖口平滑过渡。已重建两组 Blender/GLB。沿用已有材质，不能宣称本轮完成材质写实化。

## 实际画面对照

`artifacts/realism102-validation/stage101-102-carbine-comparison.jpg` 对照上轮与本轮的卡宾枪腰射、ADS 和换弹中点。原图保留在对应阶段 `source-forward/`，没有通过修图掩盖问题。同一角色位置和朝向，ADS 使用游戏正常瞄准 FOV，不是相同投影。

- 腰射：右手从横向侧伸变为较紧凑的竖向轮廓，武器和手臂的总体占屏变化有限。
- ADS：红点保持居中，未见新增手臂遮挡；枪体仍厚重，表面金属与聚合物的差异不足。
- 换弹中点：过长握把的露出段缩短，右手移到握把下部。但掌位偏低、拇指形成环状，四指并未呈现可信的完整包握。当前截图不能支持“自然握持已完成”，下一轮必须按握把接触面调整掌骨、虎口和每根手指，不能只整体旋转手部。
- 背景仍有重复草簇、相似平顶建筑、灰白远山和重复树形。本镜头不覆盖第三人称人物的完整审阅。
- 已查看霰弹枪换弹中点原图：右手位于握把右下侧，虎口未贴合握把；共享手型调整没有解决各枪的独立接触。精确射手步枪腰射中枪体和瞄准镜仍显得光滑、缺乏材质层次。下一轮需同时检查三枪，避免只看卡宾枪。

## 验证与边界

证据集中于 `artifacts/realism102-validation/`。`topology.log` 记录两组生成网格有效及 Hold、Reload、Throw、Heal 四个片段导出通过；这不是手部解剖或穿模检测。导入退出 0 仍有 `Parameter "t" is null` 错误，未解决。

首次验证驱动在源码截图阶段退出 143，原因未知，见 `driver-interruption.json`；使用 `--resume` 保留已成功的检查，重新执行中断的截图任务。最终结果以 `test-results.json` 和 `verification.json` 为准。

规则检查覆盖单机、瞄准、换弹、武器遮挡、入口/屋顶碰撞及网络状态等；网络状态规则不等于真实多人联机。现有真实联网驱动依赖认证后端和服务器凭据，本轮未运行该驱动或读取凭据。截图使用 Forward+ / llvmpipe，不证明硬件 GPU 性能。

本地运行方法见 `artifacts/realism102-preview/README.md`。整体状态 `continue`：第一人称形体与材质、人物、场景差异、光照、真实联网及更广泛碰撞仍有工作，不能将本轮比例修正当作整个目标完成。

最终验证已完成：源码与预览包各 11 项功能检查通过，加上导出和两次截图采集共 25 条成功记录；30 张 PNG 和 11 个构建文件哈希核验通过。已查看源码、包内三枪五姿态总览及上述原图，ADS 未见新增手臂遮挡；换弹姿态仍清楚暴露包握接触不足。证据为 `test-results.json`、`verification.json`、`source-forward-contact.jpg` 和 `packaged-forward-contact.jpg`。这些通过记录不改变上述画质和真实联机验证边界。
