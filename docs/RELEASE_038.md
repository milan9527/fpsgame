# 0.38.0-dev 运行服务升级

本次开发发行加入机器人提前转移、驾驶员等待队友与危险中断、机器人主动搭乘和安全下车。默认 Linux 包、发布 API 和单人/双人专服已升级为 **0.38.0-dev / 协议 17 / ash-valley-18 / 数据库 0004**。完整商业级游戏目标仍未完成。

驾驶员为车门旁可正常上车的队友最多等待 3 秒，受伤、车体受损或附近可威胁车体的破片手雷会结束等待。机器人可搭乘附近停稳的同队车辆，驾驶员离车后等待停稳并通过正常出口检查下车。出口受阻时保留座位并重试。当前没有远距离追车、完整道路寻路或倒车脱困。

Linux x86_64 桌面解压后运行 `./play.sh`，需要 OpenGL 3.3。离线 SOLO/DUO 无需账号；联网在界面输入自选用户名和密码，点击 **CREATE ACCOUNT** 注册，之后登录。用户名 3–24 位字母、数字或下划线，密码 10–128 位；开发和发布账号库独立。在线客户端和服务须匹配完整版本信息。上述回环地址不是外部玩家可直接连接的公网地址，公网可达性尚未验收。

## 验证与数据保留

50 项构建检查（导入/导出及 48 项包内规则）、重新解压启动、4 项实际渲染、95 项隔离后端测试和非 root 专服镜像检查通过。存量数据库在新后端启动后保持全字段指纹一致。

打包联网验证包括真人账号自动客户端驾驶、机器人副驾驶上车和下车；机器人驾驶员等待乘客；邀请连续两局；四客户端救援、队伍胜负、战绩落库、标点与合成语音转发；延迟/丢包/短时中断下观战；驾驶员断线/撤销及移动交火。正常时间 solo/duo 对局约 92.48/81.80 秒完成结算；两场均未观察到机器人驾驶，不能据此宣称自然用车率改善。

发布工具在房间空闲、无预约、结果队列为空时备份数据，保留旧镜像与归档，等待旧租约失效后切换固定镜像。现有 PostgreSQL/Redis 数据卷保留，切换前后 users/matches/results 全字段指纹一致。发布端口两个单人客户端、双人邀请连续两局，以及切换后备份隔离恢复通过。证据目录 `artifacts/release-0.38.0-dev/` 包含 `verification.json`、`solo-clients.log`、`duo-requeue.log` 和 `post-release-restore.json`。本次未触发故障回退。
