# Stage105：装卸区建筑轮廓、庭院草缘与棚下阴影

依据整体环境优先审阅，本轮结束武器连续微调，将主仓库（35,34）改用绿色坡屋顶外观，后排仓库（68,34）使用另一屋顶样式，并在主仓库西侧增加装卸棚、立柱、斜撑、混凝土地坪及两只货箱。庭院边缘增加连续但不规则的低草过渡，降低草高并提高候选密度。修改集中在 `client/scripts/world.gd`、`client/scripts/world_visuals.gd`。使用原有资产与光照；新增遮挡形成棚下阴影，本轮没有重做全局照明或武器手臂资产。

实际查看源码入口斜视、装卸区远侧和棚下截图，以及包内棚下截图。正常第一人称机位中，绿色山墙与较高屋顶改变了原先平顶盒子的轮廓；装卸棚、支撑结构和货箱明确了建筑用途，阴影让物体更贴地。庭院草缘比原来零散的草点连续。局限依然明显：混凝土地坪边界过于笔直、招牌字偏小、远景树木均匀散布、山体平滑、其他仓库仍重复。手臂仍显圆柱化，手指与握把接触不自然，不能将这一组环境改善视为整体画质目标完成。

根据新增验证范围反馈，除了原仓库入口，还专门验证了西侧装卸棚：真实角色沿 x=23.5 双向经过棚下，终点分别为 z=24.93323、43.06677；站姿通道射线畅通、顶棚和立柱射线被挡。两只货箱侧面射线命中 x=24.05，可见模型变换后边界与 2.5×1.5×2 米隐藏碰撞代理吻合。六根旋转斜撑均按实际全局变换后的局部采样点检查射线碰撞。这些测试在源码和导出预览包内都运行，而不是只检查未旋转包围盒或仓库中心通道。

证据位于 `artifacts/realism105-validation/`。`depot-results.json`、`environment-results.json` 保存新增结构检查；`test-results.json` 保存导出、瞄准108样本、武器遮挡、单机烟测、入口与屋顶碰撞、网络状态规则及截图检查。静态截图采集冻结游戏逻辑，仅用于画面审阅；角色通行测试独立推进实际物理过程。网络状态规则不代表真实认证多人会话通过。使用 llvmpipe 软件 Vulkan，不能代表硬件 GPU 性能。

本地预览：`./artifacts/realism105-preview/Linux/IronMeridian --path /tmp --rendering-method forward_plus`，保留相邻 PCK。这是 Godot 可执行文件加导出资源包，未发布。下一阶段优先改善正常视角中的硬直地坪接缝、道路边缘、树丛疏密与地形材质/光照层次，并继续保留人物、武器手臂、真实联网及更广范围碰撞验证目标。

已查看 `stage104-105-environment-comparison.jpg`：相同机位的腰射与 ADS 都能辨识新增棚体、坡屋顶和草带，不能把 ADS 变焦误认为环境变化。源码三枪五姿态总览保留了各自瞄准与换弹画面；卡宾枪红点视窗、霰弹枪机械瞄具、精确射手步枪圆形镜面仍可见。镜片偏绿、换弹中段支撑手离枪与圆柱袖子仍显生硬，本轮没有宣称武器或手臂质量改善。包内装卸区远侧全分辨率截图也显示两只货箱与支撑结构，棚体不是只有碰撞代理。

最终汇总：27 条验证记录全部成功（20 条功能检查、6 条截图采集、1 条导出），源码与包内各 20 张、共 40 张 1280×800 截图。`verification.json` 保存检查结果、图像尺寸及构建文件哈希，最终验证日志未检出 ERROR/WARNING。已直接审阅包内三枪五姿态总览及卡宾枪腰射/ADS 原图：红点居中，新增棚体、屋顶和草带在相同机位均可辨识；绿色镜片、换弹手部接触与圆柱袖子问题仍存在。预览包已实际运行验证；整体状态 continue。
