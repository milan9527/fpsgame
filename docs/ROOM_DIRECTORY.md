# 房间目录与名额预留

Godot 客户端默认使用房间目录匹配，专服报告真实心跳和已接纳玩家。Compose 启动 `game`（UDP 27015）和 `game2`（UDP 27022），分别保存本地结算发件箱；两者共用账户、数据库和 Redis。当前是固定两实例池，尚无自动扩缩、跨区排队或断线重连。

新接口：

- `POST /internal/rooms/heartbeat`：专服密钥鉴权，报告房间编号、进程实例 UUID、回合 generation UUID、递增 revision、地址/端口、容量、阶段和已接纳玩家 UUID 列表。房间有效期 12 秒；专服每 2 秒报告，阶段或成员变化时提前报告。
- `POST /matchmaking/rooms/join`：账户 JWT 鉴权。可指定房间，也可自动选择；只分配版本兼容、仍存活、处于 waiting/lobby 且有余量的房间。返回具体地址、端口、房间绑定和 45 秒票据。
- `POST /internal/rooms/tickets/consume`：专服密钥鉴权，按房间、实例和回合绑定一次性消费。错误房间不会烧掉正常票据；房间失效、已开始或回合变化时拒绝入场。

容量计算包含已确认玩家和未过期预留。分配、用户占位和票据创建在同一个 Redis Lua 操作中完成。消费票据后，预留仍占容量，直到心跳确认该玩家或 45 秒到期，防止“票据已消费、玩家尚未报告”期间超卖。

每个用户只能持有一份新目录预留或活跃房间占位。已确认用户随心跳刷新 15 秒占位，断开后从下一次心跳移除。新回合清理上回合未确认预留；旧回合票据无法跨回合使用。失联时可能需要等待剩余占位到期，尚无取消、重连或会话迁移接口。

同一房间仍存活时拒绝其他进程实例接管；revision 必须严格递增，过时报告不延长存活时间。实例内地址/端口/版本保持不变，同一回合容量保持不变；从 live/finished 回到候场必须更换 generation。报告不能抢占已属于其他房间的用户。

实现面向当前单 Redis 实例，Lua 使用同一实例的多个键；尚不支持 Redis Cluster 跨槽部署。旧 `/matchmaking/join` 与 `/internal/tickets/consume` 暂保留供旧 API 回归测试，当前 Godot 不调用，也不接受它们生成的未绑定房间票据。

验证：

- `backend/tests/test_rooms.py` 在真实 Redis 上验证 20 个并发请求争抢两个各 2 人房间、同账户并发预留、票据绑定/一次消费、心跳确认前后容量、回合隔离、过时报告、过期边界及 HTTP 鉴权与模式校验。过期测试直接推进存储边界，并检查配置的 TTL，不代表长时间稳定性测试。
- `tools/test_room_api.py` 通过运行中的 HTTP API、真实 QA 账户和合成专服心跳验证两个不同地址的票据分配、用户占位与并发消费。它没有启动第二个 Godot 专服。

- `tools/test_multiroom.py` 启动两个真实客户端，分别进入两个 Compose 专服，验证不同回合编号、名单隔离及最后一人离开后恢复候场。
- `tools/test_room_failure.py` 仅在第二房间为空时停止实际进程，等待超过 12 秒，验证目录过期与匹配拒绝，然后恢复专服并确认新实例注册。

专服默认房间名为 `room-<GAME_PORT>`，可用 `GAME_ROOM_ID` 指定；`GAME_PUBLIC_HOST` 是客户端连接地址。启动时先通过版本检查、创建监听并注册房间，注册失败不会宣告就绪。进程重启最多等待旧实例租约到期；连续超过 10 秒未成功报告时拒绝新入场。候场预留的 generation 在首位玩家进入时保留，进入后续回合才更换。最后一名真人离开进行中对局时立即保存结算、清理世界并恢复候场，不等待机器人继续打完整局。

调试客户端可用 `TEST_ROOM_ID` 选择房间；临时测试专服按独立端口注册。延迟代理保持真实房间编号，仅转发连接端口。普通客户端自动选择可用房间，无房可用时短暂重试后显示失败提示，尚无持久排队。

退出程序会通过可靠通道请求离开，并最多等待 2 秒确认后结束网络轮询。专服为连接设置 5–10 秒 ENet 超时范围，以回收突然失联连接；这是当前配置，尚未完成长期移动网络验证。
