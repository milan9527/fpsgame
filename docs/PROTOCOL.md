# 客户端、专服与 API 兼容性

唯一版本清单是 `client/protocol.json`。Godot 客户端和专服读取同一资源；API 镜像构建时复制该文件，发行 PCK 也包含它。

| 字段 | 当前值 | 更新规则 |
|---|---|---|
| `protocol` | `4` | 改变 RPC、输入、快照或其他不兼容网络语义时递增 |
| `content_revision` | `ash-valley-1` | 改变地图碰撞或需要各端一致的游戏资源/规则时更新 |
| `client_version` | `0.5.0-dev` | 人类可读发行版本；仅用于提示，不决定兼容 |

兼容要求前两个字段完全一致。客户端在登录前查询 `GET /protocol`，不兼容时显示升级提示；匹配 API 在签发票据前再次验证。Redis 票据存储协议和内容版本；专服消费票据时也检查绑定，错误版本不会烧掉正常票据。消费检查与删除在同一 Lua 脚本内执行。

协议 4 将跳跃、换弹、治疗、拾取、投掷和切枪迁移到通道 4 的可靠有序 RPC。它携带回合 ID、操作序号和操作时的视角；移动输入仍在通道 1 不可靠有序传输，服务器忽略其中的一次性操作字段。可靠操作按独立序号去重，旧回合/已死亡/非进行中状态拒绝；落后最新移动超过 120 个输入序号的积压请求丢弃。操作预算每秒恢复 10 次、最多积累 10 次，限流拒绝的序号也会被消费，不能稍后重放。游戏冷却和库存规则继续生效；可靠送达不代表在无弹药或冷却中强制执行。

专服启动时用服务密钥请求 `/internal/build/check`，成功后才监听 ENet 端口。不兼容或 API 不可用会导致进程非零退出，Docker 可按重启策略重试。API `/health` 同时提供数据库与协议版本。

修改清单后，重新构建并一起部署 API、专服和客户端：

```sh
docker compose up -d --build api game
./tools/package.sh
```

当前采用停服协调升级：应先等待现有对局结束，再执行部署并分发新客户端。这条命令本身不会等待对局结束。旧客户端会被明确拒绝；尚无多版本房间调度、自动补丁分发或无中断滚动升级。

版本声明是兼容性检查，不是二进制完整性证明，不能替代反作弊。允许恶意修改的客户端伪造版本字段，不应据此信任其游戏输入。

验证入口是 `tools/test_protocol.py`、`tests/protocol_client.gd` 和 `tools/test_protocol_server.py`。前两项需要运行中的本地 API，专服测试会启动临时不兼容进程并确认它没有开始监听。完整回归见 `tools/verify.sh`。
