# Stage115 环境阶段实机审阅

本轮为仓库西侧增加可穿行的弧顶维修棚、工作台与结构肋，加入维修院落碎石、车辙和道路泥土过渡，并清除硬化场地中的植被。正常宽幅视角可以辨认新的建筑轮廓与院落用途；整体画质目标仍未完成。

## 画面与相机

`artifacts/realism115-validation/final-forward/` 保存最终独立包的宽幅地形、仓库入口近景、院落、室内和林地截图。七个环境机位复用114归档截图；新增维修棚机位另用114独立包拍摄前图。位置、目标、yaw/pitch、眼高和1280×800分辨率保存在两个 `*-camera-poses.json`。`camera-comparison.json` 核对前后完整相机记录；三个 `*-before-after.jpg` 供直接比较。

维修棚机位：角色 (15.5, 0.05, 40)，看向 (15.5, 2.6, 29.5)。宽幅：角色 (17, 0.05, 50)，看向 (-46, 12, -90)。入口：角色 (35, 0.05, 44)，看向 (35, 1.9, 34)。实际眼高增加1.6米，朝向详见JSON。

审阅发现：弧形轮廓打破局部仓库的平直天际线；裸露院落与草地、路肩之间出现可辨的用途差异。原仓库入口仍可看见内部与后门。限制：新棚内表面偏亮，密集金属条纹存在锯齿/摩尔纹；大面积平地、远山折面、重复仓库与规则植被仍明显。没有修改全局光照参数，也没有重新制作植物几何，不能将局部材质及阴影差异称为整体光照或植被完成。

## 功能与证据边界

新增 `tests/service_yard_traversal_review.gd` 使用真实角色 move_step、重力和物理帧双向穿棚，同时检查侧墙与弧顶碰撞。初测确实失败：随机补给箱位于 (14.88349, 0.75, 30.09325)，阻塞中间通路。已在生成阶段排除维修棚及两端入口范围内的随机箱，修复后的源码测试通过；失败日志保留，不能用早期包作为最终预览。

最终包检查记录以 `final-functional-results.json` 及对应 `final-*.log` 为准，覆盖瞄准、枪口遮挡、单机启动、入口/屋顶/棚下/掩体碰撞、本地网络状态规则、原仓库/装卸棚/新维修棚双向物理通行。早期 `functional-results.json` 属于修复前诊断，不作为最终全通过证据。

环境截图进程在七张PNG及相机JSON落盘后被中断，没有收集到该进程退出码和PASS日志；这批截图只作为可复核图像及相机证据，不宣称截图脚本正常退出。维修棚截图单独补跑并保存退出结果。渲染使用 Forward+ / llvmpipe，未测硬件GPU性能。

真实双客户端联网本轮未验收：前轮已记录现有runner依赖服务密钥/认证fixture，本轮未读取认证或密钥。网络状态规则通过仅代表本地逻辑。本轮未完成第三人称重拍或第一人称连续换弹验收；先前武器阶段证据不能代替这些剩余验收。
