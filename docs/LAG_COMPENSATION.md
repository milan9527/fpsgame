# 服务器命中延迟补偿

在线玩家的即时射线武器使用服务器历史胶囊体。单机、机器人和刚进入对局尚无足够历史时，继续使用当前物理射线。手雷仍由服务器实时刚体与爆炸规则处理。

每个权威物理帧先移动全部角色，再保存位置、碰撞高度和爆头高度，最后处理射击。历史最多保存 32 帧；换局清空。查询在相邻帧之间插值位置，姿态在记录边界切换；超过 3 米的位置跳变不生成可命中的插值轨迹。已经死亡或移除的角色不会再接受历史伤害。

回溯量为服务器 ENet 测得的 RTT 加 50 毫秒显示延迟估算，最多 200 毫秒。RTT 覆盖服务器状态下行、玩家输入上行的合计时间；50 毫秒近似当前快照/远端平滑产生的额外延迟。客户端不能提交命中结果、历史姿态或自选时间。高延迟会受到上限限制；这不是对客户端实际渲染帧的精确重建。ENet RTT 的平滑、网络抖动及角色转向仍会产生误差。

射击起点使用射手当前权威眼部位置。先对静态世界做射线，再在挡墙距离以内求历史胶囊体最近交点。真实物理角色完全不移动，因此不影响移动碰撞、导航、爆炸和并发射击。历史命中使用对应历史姿态的爆头阈值，伤害、护甲、射速、散布和击杀归属仍走原有服务器规则。

取舍：目标刚躲到掩体后，仍可能被最多 200 毫秒前的可见位置命中；当前射手身前的墙始终挡弹。动态门、车辆和可破坏掩体尚未实现，这些物体加入后需要相应的历史遮挡策略。

验证：

- `tests/lag_compensation_rules.gd`：解析胶囊体、插值、姿态、真实武器伤害/爆头反馈、静态墙、死亡/瞬移过滤、历史容量、换局和物理状态不变。
- `tools/test_delayed_online.py`：本地 UDP 代理给两个真实 Godot 客户端的上下行分别添加 70–90 毫秒延迟，覆盖登录、开局、动作、手雷、声音、预测校正和退出，并检查服务器实际启用回溯的日志。

后者属于短时延迟与抖动集成测试，不覆盖丢包、断线重连、16 真人负载或长时间稳定性；前者的可控历史命中检查也不能替代真人手感调优。
