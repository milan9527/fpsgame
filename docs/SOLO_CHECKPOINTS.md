# 单机保存与继续

单机回合进行中，单人角色存活或双人队伍尚未淘汰时，在暂停菜单选择 SAVE OPERATION & RETURN。写入成功后返回主菜单，不记作放弃；失败时保持当前对局暂停并显示原因。主菜单 CONTINUE SAVED OPERATION 加载后先暂停，玩家点击 RESUME 才继续模拟。在线对局没有此功能。

当前为一个手动保存槽，已有文件时按钮明确显示 REPLACE SAVED OPERATION & RETURN。开始另一场新单机不会自动删除旧存档，但再次保存会替换它。没有自动保存。直接关闭进行中的游戏或选择 ABANDON 会按既有流程记为放弃，角色被淘汰或回合结束则结算完成。已结算或待写入结算的回合不能再从旧检查点重开；此功能用于挂起继续，不用于死亡后的读档重试。

保存内容包括相同回合 UUID、16 个角色的生命/护甲/三枪弹匣/储备/医疗/投掷物、位置速度和姿态、换弹治疗及射击冷却、机器人目标与最后目击记忆、地图物资、当前及未来缩圈中心、回合时钟与随机状态、在途手雷的位置/速度/角速度/引信、烟雾位置/年龄和个人路标。恢复后重新生成固定地图并重建导航。临时输入、网络历史、音频播放进度、骨骼动画相位和缓存路径不保存，机器人会重新寻路；不是逐帧确定性重放。

文件为 `user://solo_checkpoint.dat`，带格式版本、内容版本和 SHA-256 校验，最多 2 MiB。读取在修改现有场景前检查结构、库存、数值范围和资源数量；不解码可执行对象。内容版本不兼容或损坏时不加载。写入采用同目录临时文件加重命名替换；再次保存前保留上一次有效主文件为 `.bak`。主文件不可读时尝试备份并提示恢复了较早检查点。备份可能属于先前保存的另一场操作，且仍受回合已结算检查约束。首次保存没有旧备份，同盘备份不防磁盘损坏，也不承诺断电耐久性。

本地结果仍使用独立的不可变记录目录。检查点不会上传到在线排行榜，也不更改在线专服状态。恢复前检查已发布结果目录和待存结果，避免同一 UUID 再次结算。校验值用于发现损坏，不是防止用户修改离线存档的安全机制。

`checkpoint_rules.gd` 覆盖状态往返、尸体/库存/计时、手雷/烟雾、缩圈/随机数、保存失败、备份、无放弃记录和已结算隔离。`test_checkpoint_process.py` 使用六个独立 Godot 进程分别验证单人与双人验证关闭进程后继续同一回合，并对发行 PCK 运行同样检查。


开发版增加 `DUO / OFFLINE TEAM OPERATION` 入口。双人检查点格式 2 保存每个角色的队伍编号、倒地状态/生命、流血时间、击倒来源、救援目标与剩余秒数，以及已淘汰队伍名次。读档按保存的队伍重建关系和排名，不重新配对；倒地与扶起进度从保存处继续，阵亡成员可在队友仍存活时挂起观战。旧单人格式 1 继续兼容。两种模式共用上述单个手动保存槽；保存另一场操作会替换它。

格式校验拒绝人数错误、同队不同名次、非法救援关系/击倒来源和倒地状态矛盾。`tests/duo_checkpoint.gd` 验证菜单入口、倒地/救援进度、已淘汰队伍排名、观战恢复及随队胜利后的旧档隔离，证据 `artifacts/duo-checkpoint.log`。跨进程证据为 `artifacts/duo-checkpoint-process.log`；旧单人回归为 `artifacts/duo-checkpoint-solo-regression.log`。这些改动仍在组队开发分支，已发布 0.34 包未替换。
