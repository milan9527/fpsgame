# Stage131 弹匣交换与动作回归

本轮承接 stage130 审阅发现的弹匣交换缺失：第一人称换弹分为拔出旧匣、下探、抬起替换匣和插入。替换匣独立控制可见性，支撑手跟随当前弹匣；完成或切枪后恢复初始状态。三种武器共用此过程，霰弹枪仍为项目现有的弹匣供弹设计。没有修改环境资产，不计作建筑、植被或光照提升，整体目标未完成。

## 证据方法

以 stage129 已导出包作为修改前基线（stage130 未改运行时），stage131 导出包作为修改后。两侧加载同一个外部动作采集脚本，角色按 60Hz 模拟推进，三枪执行腰射持枪、瞄准、真实 shoot 调用及换弹，然后执行第三人称走、跑、蹲下、蹲行、起立、开火和换弹。其他角色冻结，不能作为完整对局或帧率验收。

本轮使用 `REVIEW_KEYFRAMES=1`：第一人称换弹在段内第 24、48、72、96、120 tick（零起算，存在时）抓图，其他动作仅抓末帧，跳过稳定与切枪段。JSON 中 `render_every_ticks: 12` 是默认采样间隔，本轮实际记录以 `samples` 和本说明为准。稀疏采样不能证明动作中间绝无穿插，第三人称换弹末帧尤其不能代替整个换弹过程的接触审阅。

第一人称初始位置 `(17,0.3,50)`、yaw=0、pitch=0.1；第三人称起点 `(0,0.3,68)`，相机相对角色偏移 `(2.8,1.5,-3)`、FOV=42，朝向角色上方 0.95 米。实际相机世界位置和旋转（弧度）、角色位置、动作与时间见两侧 `action-timeline.json`。第三人称持最后切换的狙击枪；不能与 stage130 步枪截图直接比较枪械接触。

最初抓图未等待 Node3D 延迟变换同步，出现替换匣显示在旧位置的误导画面。修正为渲染前等待两次 process_frame 后重跑。`before-unsynchronized/`、`after-unsynchronized/` 与旧 `before.log`、`after.log` 属于中断尝试，不作为最终通过证据；有效证据只使用 `before/`、`after/` 和 `*-synchronized.log`。元数据中的 `magazine_position` 指原弹匣，不能当作替换匣的位置证明。

## 功能与限制

最终两次采集均退出0，各31张；对照工具逐帧确认相机位置、朝向、角色位置、动作与tick一致。每侧7张第三人称帧、28条人物无遮挡射线通过。可复核入口为 `artifacts/realism131-validation/review.html`，汇总为同目录 `verification-summary.json`。

已逐张审阅三枪换弹对照拼图，以及第三人称奔跑、蹲行原图。改后旧匣下探、空弹匣井与抬起替换匣的动作更清楚，但部分下探阶段位于屏幕下缘，不能声称交换全过程清晰可见。握把手掌仍偏方，腕袖衔接生硬；第三人称脸部过暗，蹲行膝部与靴子拥挤，胸前弹袋仍像方块。背景建筑立面、树形和地表草斑重复，宽路及院落空旷；本轮没有解决这些环境问题，也没有完成用户要求的环境改进组和入口、宽幅地形专项对照。

最终包单机冒烟通过 16 角色、换弹、治疗、伤害、胜利状态、射线、掩体、射击间隔和骨架检查，属于隔离状态验证，未完成正常整局人工游玩。三枪换弹接触检查通过 183 个样本及 6 个切枪中断相位；瞄准对齐通过 108 个样本。三枪门洞实际 shoot 命中、墙后无伤害检查通过，仓库双向通行通过：x=23.5，z=44→18.42486 与 18→43.57514。

本地网络状态规则通过，但真实双客户端认证联网未验证。现有联网测试依赖服务端认证凭据；本轮未读取密钥、修改认证或用规则测试冒充真实联网，后续仍需可授权使用的测试会话或夹具。

本地启动：

```sh
./artifacts/realism131-preview/Linux/IronMeridian --path /tmp --rendering-method forward_plus
```

需要图形桌面与 Vulkan。主菜单进入单机，WASD 移动，鼠标转向，左键射击，右键瞄准，R 换弹。包身份见相邻 `build.json`。本轮实机使用 llvmpipe 软件渲染。

下一阶段回到环境优先级：在正常游戏视角改善可进入建筑的体量与院落用途、近景地表草灌分布和阴影层次，保存同机位前后、入口近景和宽幅地形图并验证通行碰撞。人物正面过暗、蹲姿膝靴轮廓和手腕袖口仍保留为后续缺陷，不以本轮局部动作改进宣称整体完成。
