# 本地战绩

`local_profile.gd` 保存离线结果，默认路径为 Godot 用户目录下的 `local_results`。Linux 通常位于 `~/.local/share/godot/app_userdata/Iron Meridian/local_results`。此目录不包含在线令牌或密码，不参与在线排行榜。

每局使用独立 UUID 目录：

```text
local_results/
  records/<operation-id>/result.json
  records/<operation-id>/backup.json
  pending/<random-transaction-id>/...
```

先向唯一的暂存目录写入并刷新两份文件，再在同一文件系统内原子重命名为结果目录。汇总只读取已发布目录，中断的暂存写入不会计入统计。多个进程保存不同对局不会覆盖共同的总计文件，因为总计由记录重新计算。已发布的非空目录不可被覆盖：相同内容重试成功，不同内容或未来版本冲突会被拒绝。

版本 1 保存操作 ID、UTC 时间、完成/中止状态、名次、击杀数、秒数和地图标识；旧记录始终按单人解释。开发分支的新记录使用版本 2，另存 `mode: solo | duo` 与 `team_id`（单人 0，双人 1–8）。读取器兼容两个版本，不原地改写旧文件。读取时限制单份文件大小，验证结构、数值范围及 SHA-256。主副本不可读时使用备用副本；两份都不可读则保留文件并提示汇总不完整。遇到未来版本不会回退到旧副本覆盖它。校验用于发现损坏，不是防篡改认证。

游戏在结算、正常离开单机及正常退出时记录结果。单人死亡后离开采用当时确定的名次与击杀；存活时离开记为中止。双人个人阵亡而队友仍存活时，名次尚未确定，此时离开记为中止；留下观战则可以随队友获得最终名次及胜利。整队已淘汰时可立即记录已确定的队伍名次。重复结算由游戏内操作 ID 和存储层共同去重。写入失败的结果暂存在当前进程内，菜单可重试；正常退出会先提示，用户明确选择后才丢弃尚未保存的结果。

备用副本与主文件位于同一磁盘，不能替代磁盘备份。可以在退出游戏后备份整个目录。本实现不承诺断电耐久性；强制终止进程可能丢失尚未发布的结果。战绩目录不保存进行中的世界状态；单机保存/继续另见 [单机检查点](SOLO_CHECKPOINTS.md)。

`tools/test_local_profile.py` 使用隔离临时目录和独立 Godot 进程，覆盖并发发布、重试、冲突、损坏恢复、校验与版本拒绝，并通过真实游戏/UI 测试结算、中止、失败重试和退出保护。`--capture-ui` 使用真实渲染器截图，`--packed` 验证发行包。其他游戏测试显式禁用本地战绩写入，不污染玩家数据。


历史页面显示每条记录的模式，并分别汇总单人与双人的完成数、胜利数；总体统计仍包含两者。一个操作 ID 的模式与队伍不可通过重试修改。在线对局不进入本地战绩。

`tests/local_duo_profile.gd` 验证 v1/v2 混合读取、阵亡成员随队获胜、尚有队友时退出、整队淘汰后退出、模式校验、不可覆盖与失败重试。`tools/test_local_profile.py` 在另一个 Godot 进程重新读取混合记录，确认落盘后的模式统计。证据为 `artifacts/local-duo-full-regression.log`，截图为 `artifacts/local-duo-history.png`。双人进行中检查点仍未实现，不能将战绩保存视为对局存档。
