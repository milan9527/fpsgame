## 重试实机审阅

`before-retry/process-result.json` 与 `after-retry/process-result.json` 均为正常退出、exit 0、passed true，分别耗时 381.834s、378.628s。两个目录均包含上述三机位的原始 PNG 与相机记录。`road-before-after-comparison.png` 是道路图相同区域的上下排列，顶部为修改前，底部为修改后；完整画面仍以原始截图为准。

道路外侧由平直表面变成缓起伏土坡，但同机位对照显示宽泥色带仍占据大面积，路面与场地之间的材质覆盖关系、尺度感没有得到足够改善。本轮不能认定“明显道路过渡修复”已经完成。下一次环境结构修改需要同时处理路肩占地宽度与场地边缘形状，而不是继续单独抬高土坡或调整颜色。入口保持通畅，远景山体与树冠问题仍在。

环境重试沿用 Forward+，未降低画质；测试在场景建立后再次禁用自动渲染，截图仍显式调用 force_draw。这不能证明初次超时的根因，部分绘制/读回仍很慢。后续仅修正了该行注释，实际重试脚本快照与输入哈希保留在证据中。

## 下一轮道路结构定位

只读追查 `world.gd` 与 `road_surface.gdshader`：平路与起伏路肩共用道路材质；普通直线路段的 terrain_join 使用中心距离约 5.6–8.4m 渐变（另有 erosion 扰动），与约 7m 车行道相比仍覆盖很宽。入口距离场另向服务口扩展。本轮只改变断面，没有改变这一覆盖范围；下一轮应将断面宽度、材质覆盖和入口距离场一起设计，再用同机位检验，不能把这条代码定位本身当作修复通过。
